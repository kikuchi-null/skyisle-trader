# 港への投資の設計

- 日付: 2026-11-07
- 状態: 実装対象。実装後のルールと操作は `skyisle-trader-design.md` にも反映する
- 対象: `game/`、`ui/ui.go`、テスト、ドキュメント

## 1. 目的

現行の経済には、ボットの実測(各 300 シード)で次の問題がある。

- Day 26 以降、出航時の資産の 86〜94% が現金で、資金の使い道がない
- 収益を制限しているのは資金ではなく市場の深さで、積載量を増やしても価格が崩れて儲からない

資金を市場の深さに変える長期投資を足し、「どの島に、いつ、どこまで投資するか」という経営判断を作る。交易の核と、他の島の現在価格を隠すルールは変えない。

成功の基準(ボットでの実測):

1. 適度に投資すると、投資なしの最善より平均スコアが上がる
2. 投資しすぎる、または遅く投資すると損をする(常に投資が正解にならない)
3. 最適な積載量の拡張回数が、投資なしより増える(拡張の選択肢に意味が戻る)
4. 中盤の現金比率が下がる

## 2. ルール

- 各島は「港」の段階を持つ。初期値は 0、最大は 2
- 現在地の島でだけ投資でき、時間を消費しない。1 回で 1 段階上がる
- 費用は 500,000G × (その島の現在の段階 + 1)。0→1 は 500,000G、1→2 は 1,000,000G。島ごとに独立し、1 島を最大にすると計 1,500,000G
- 段階が上がると、その島で 1 個売買するごとの価格の動きが小さくなる。品目はすべて同じ

| 段階 | 1 個買う | 1 個売る |
|---:|---:|---:|
| 0 | ×1.010 | ×0.990 |
| 1 | ×1.005 | ×0.995 |
| 2 | ×1.003 | ×0.997 |

- 売値 90%、揺らぎ、回復は変えない
- 全島の全段階で、売っても現在価格は属性ごとの初期値の 30% より下がらない(後述)
- 投資しても返金はない。費用は所持金から引かれ、スコアにそのまま響く
- 拡張と同じく、最終日(Day 100)でも投資できる。大量の積荷を売る直前なら、最終日の投資でも元が取れることがある
- 全島の港の段階はプレイヤーに公開する。`Estimate` は行き先の段階を反映する。段階は公開情報なので、現在価格を隠すルールは崩れない

### 判断の軸

- **場所**: 名産や需要が多い島か。島は漂流するので、投資先がいつまでも近いとは限らない
- **時期**: 早いほど回収の機会が多いが、序盤は資金が仕入れと競合する
- **積載量との配分**: 市場が深くなるほど、拡張が活きる

## 3. 数値の根拠

実測コードと全結果: 使い捨てのコピー内(リポジトリ外)。戦略はボットの貪欲法に価格の記憶を足したもの。投資は「D 日まで、2 回目以降の寄港(v1 は初回から)で、仕入れ資金を残せるときに行う」固定方針。人間の判断の上限値ではない。

候補の比較(200 シード)で、次の結論を得た。

| 値動き(千分率) | 基準費用 | 結果 |
|---:|---:|---|
| 10/7/5/3 | 1,000,000 / 2,000,000 | 全方針で投資なしを下回る |
| 10/5/3 | 1,500,000 / 3,000,000 | 全方針で投資なしを下回る |
| 10/7/5 | 300,000 | 効果が小さい(+5〜6%) |
| 10/6/4 | 500,000 | +6〜7% |
| **10/5/3** | **500,000** | **+19%。下記** |
| 10/5/3 | 800,000 | +6% |

採用値の検証(300 シード、単位は百万 G)。

| 戦略 | 平均 | p10 | p90 |
|---|---:|---:|---:|
| 投資なし・拡張 0 回 | 8.19 | 5.89 | 10.75 |
| 投資なし・拡張 2 回(従来の最善) | 9.63 | 6.12 | 13.13 |
| 投資なし・拡張 5 回 | 8.31 | 4.46 | 12.40 |
| 拡張 2 回・3 島を段階 1(〜D40) | 10.95 | 6.62 | 15.64 |
| 拡張 3 回・寄港した島を段階 2(〜D40) | 11.55 | 5.84 | 17.83 |
| 拡張 3 回・同(〜D99、遅い投資も続ける) | 9.43 | 2.51 | 16.42 |
| 拡張 5 回・同(〜D60) | 10.88 | 4.22 | 18.43 |
| 拡張 0 回・同(〜D40) | 7.48 | 4.51 | 10.95 |
| 往復・投資なし(拡張 3 回) | 5.89 | 2.93 | 9.64 |
| 往復・2 島を段階 2(拡張 3 回) | 9.64 | 4.08 | 15.56 |
| 2 手読み・投資なし(拡張 3 回) | 12.03 | 8.43 | 15.31 |
| 2 手読み・寄港した島を段階 2(拡張 3 回) | 14.13 | 9.46 | 19.29 |

基準との照合:

1. 達成: 最善の平均が 9.63 → 11.55(+20%)
2. 達成: 同じ方針でも、投資を D99 まで続けると平均 2.1M 下がる。拡張 0 回で積極的に投資しても 8.19 → 7.48 と損をする
3. 一部達成: 最善の拡張回数は 2 回から 3 回へ増えた。拡張 5 回は最善との差が 1.32M から 0.67M に縮んだ
4. 達成(中盤まで): 拡張 3 回の現金比率は D26〜50 で 0.82 → 0.57。ただし D76 以降は 0.93 → 0.92 でほぼ変わらない。終盤に回収できない投資を避けるのは正しい判断なので、これは許容する

わかっている副作用:

- **結果の幅が広がる**: 積極策は p90 が大きく上がる一方で p10 は少し下がる。段階 1 を数島に広げる堅実な方針(p10 6.62)もあり、選択肢として成り立つ
- **往復が強くなる**: 平均 5.89 → 9.64。ただし巡回の投資(11.55)を超えない。上位 2 島の訪問シェアも 0.54 → 0.63 に上がる。漂流が距離を変え続けるので許容するが、バランス調整の監視対象にする
- **スコアの目安が上がる**: 上位は 1,500 万 G を超える。仕様の目安を更新する

### 価格の下限を足した理由

実装レビューで、移動せずに毎日「大量に売って買い戻す」だけで稼げることがわかった。原因は投資の前からある。切り捨てのため、価格が低いと 1 個ごとに 1G ずつ下がって 0G に達し、0G のまま無料で買い戻せる。価格 334G 未満では段階 2 の買値も上がらない。

往復の最大利益を全探索した結果(揺らぎと資金制約なし、99 日、全品目 × 全属性、重さ 1,100 まで、1 日 1〜3 回の往復):

| 価格の下限 | 段階 0 | 段階 1 | 段階 2 |
|---|---:|---:|---:|
| なし(下限 1G で近似) | +1,642 万 G | +1,922 万 G | +1,826 万 G |
| 固定 1,000G | −1.6 万 G | +264 万 G | +92 万 G |
| 初期値の 20% | +4 万 G | +31 万 G | +83 万 G |
| **初期値の 30%** | **−1.6 万 G** | **−1.7 万 G** | **−1.7 万 G** |

下限なしでは、ボットの正攻法(最善 1,155 万 G)を上回る。初期値の 30% で、この探索の範囲では往復の最善が「1 個だけの往復で損をする」になる。

最終レビューで、揺らぎを含めて完全に予見する場合の理論値も調べた(資金制約なし、3 シード)。切り捨ての非対称で、1 島全品目の合計で最大 +123 万 G(段階 2)が残るが、その島への投資費 150 万 G を下回る。実 API と資金制約のもとで試した往復・部分売買・買いだけ・揺らぎ投機は、費用込みで最大 +3.9 万 G だった(30 シード)。2 島間で売り崩して買い直す単品往復でも正攻法に届かなかったが、ボットの巡回には組み込んでいない。揺らぎの下限(初期値の 70%)より十分低いので、通常の交易には届かない。下限の追加前後で、ボットの平均スコア(上の表)は全行が同じだった。

この変更で、価格が下限に届くプレイだけ結果が変わる。`TestGolden` のハッシュは、下限を足すときに更新した(下限を無効にすると元の値に戻ることを確認した)。島の位置と基準価格の推移は変わらない。

## 4. 実装

### game

- `Island` に `Port int`(港の段階)を足す
- 値動きの表を足す: `var PortImpacts = []int{10, 5, 3}`(添字は段階、単位は千分率)。最大段階は `len(PortImpacts) - 1`
- `buyImpactPct` と `sellImpactPct` は消す。段階 0 の千分率 10 は `p*1010/1000 == p*101/100`(切り捨ても含めて同じ値)なので、下限に届かない限り既存の結果は変わらない
- `minPricePct = 30` を足す。売りの次の価格は `max(price*(1000-impact)/1000, Init*minPricePct/100)`
- `trade` と `quote` を `Market` のメソッドにし(下限に `Init` が要る)、千分率の引数を足す。呼び出し元(`Quote`、`Estimate`、`MaxTrade`)が該当する島の値を渡す。`TestBalance` の呼び出しも更新する
- `Market.SellPrice` は値動きを使わないので、`m.trade(m.Price, false, 0)` の金額だけを使う
- 追加する API
  - `InvestCost() int`: 現在地の次の段階への費用
  - `CanInvest() error`: 最大段階なら `ErrMaxPort`、所持金不足なら `ErrNoMoney`。この順で判定する
  - `Invest() error`: `CanInvest` を通ったら所持金を減らし、段階を上げる。失敗しても状態は変わらない
- 投資は乱数を使わない。投資しても、基準価格の揺らぎと漂流の推移は変わらない

### ui

- `i` で投資の確認に入る。`CanInvest` のエラーはその場で赤く出す(確認に入らない)
- 確認の種類が 3 つになるので、`confirmUpgrade bool` を `confirm confirmKind`(`confirmQuit` / `confirmUpgrade` / `confirmInvest`)に置き換える
- 確認の 3 行(パネル幅 37 桁に収める):
  - `星見島の港 1 → 2  値動き 0.5 → 0.3%`
  - `費用 1,000,000G  残金 11,345,678G`
  - `投資しますか? (y/n)`
- 相場の見出しに段階と値動きを出す: `── 相場 星見島  港 1/2 値動き 0.5% ──`。行は増えない
- 出航先の一覧に `港` の列(段階の数字)を足す。行幅は 34 桁から 37 桁になり、余白は 0 になる
- キーの説明: 通常モードの 2 行目を `[w]待機 [u]拡張 [i]投資 [q]終了` に、最終日の 2 行目を `[i]投資 [q]終了してスコアを確定` にする
- 所持金の行は区切りを 1 空白にする(`所持金 … スコア …`)。所持金とスコアがともに 8 桁になると 38 桁になり、右端が切れるため
- 成功時のメッセージ: `星見島の港を 2 に整備 (1,000,000G)`
- 地図は変えない

### やらないこと

価格の回復を速める効果、最後に見た価格の表示、投資の配当や売却、地図への段階の表示、航海日誌。効果が効く実測があるものでも、今回の判断を作るのに必須ではない。

## 5. テスト

- **ゴールデンテスト(実装前に現行コードで値を固定)**: 投資を使わない固定シードの操作列で、状態のハッシュが変わらないこと。投資の追加では値が変わらなかった。価格の下限を足すときに、意図した変更として更新した
- 往復で儲からないこと: 全品目 × 全属性 × 全段階の大量売買で、資金が減る(`TestNoWashTrade`)。価格の下限(`TestMinPrice`)
- `game`: 費用の段階、段階ごとの価格の動き、島ごとの独立、`Quote` / `MaxTrade` / `Estimate` への反映、エラーの順序と状態の不変、バランス(費用を含めて、早い投資は黒字、遅い投資は赤字)
- `randomOp` はゴールデンテストのために凍結し、不変条件と再現性のテストの側で投資を混ぜる
- 確認の文言、相場の見出し、出航先の港の列、最終日と航行中の `i` も `ui` のテストで押さえる
- `ui`: 常設のテスト `ui/ui_test.go` を足す(使い捨ての確認を常設にする)。ランダムなキー入力でパニックせず、全画面が 100 × 24 に収まりパネルが 22 行を超えない。ヘッダ・フッタ・確認の行は、大きな金額でも切る前の幅が 37 桁に収まる(`viewPanel` の `MaxWidth` が切るので、描画後では検出できない)。`i` の確認で `y` なら投資、`n` なら何も変わらない
- 実装後に、実コードの定数でボットの結果を再確認する。ボットはリポジトリに入れない
