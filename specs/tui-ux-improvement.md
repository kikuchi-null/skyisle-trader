# TUI の UX 改善の記録

- 日付: 2026-10-29
- 対象: `ui/ui.go`(主)、`game/`(表示に必要な計算の追加のみ。ゲームルールは変えていない)
- この文書は、何を課題と見て、なぜこの形にしたかの記録。**現在の画面・操作・API の仕様は `skyisle-trader-design.md` にある**

## 1. 改善前の課題(実際に描画して確認したもの)

**直感性**

| # | 課題 |
|---|---|
| A1 | 何を持っていて、どこで売れば儲かるかを、プレイヤーが頭の中で表から突き合わせる必要がある。地図・出航先一覧・積荷がつながっていない |
| A2 | 出航先を選んでも、地図上では島が光るだけ。「島は動くので、今の位置ではなく合流する地点へ飛ぶ」という看板の仕組みが画面から読み取れない |
| A3 | 売るときに、仕入れ値と比べて儲かったかがわからない(仕入れ値を覚えていない) |
| A4 | 売買の確定前に見えるのが合計額だけ。1 個ごとに価格が 1% 動くことや、確定後の所持金と積荷がわからない。`m`(最大)で浮遊苔を 148 個買う、のような損な操作をそのまま確定できてしまう |
| A5 | 待機しても何も表示されない。到着しても、そこで何が売れるかを教えてくれない |
| A6 | 残りの日数を自分で引き算する必要がある。損益(スコア)は終了時にしかわからない |
| A7 | 操作説明がすべてグレーで、キーと説明の区別がつきにくい |
| A8 | 広い端末では左上に寄って表示される。狭い端末では「広げてください」としか表示されず、必要なサイズがわからない |

**操作性**

| # | 課題 |
|---|---|
| B1 | 個数を変える方法が ←→(±1)と Shift+←→(±10)しかない。Shift+矢印は macOS のターミナルなど多くの環境で届かず、50 個を選ぶのに矢印を 50 回押すことになる |
| B2 | 買うと売るは別のモードで、切り替えるには Esc → b/s と押す必要がある |
| B3 | 売買モードのカーソルが、取扱なしの品目にも止まる |
| B4 | 出航先のカーソルの初期位置が「次の ID の島」で、意味がない |
| B5 | 航行アニメーションを飛ばせない(最大 12 日 × 200ms = 2.4 秒の待ち) |
| B6 | `u` を 1 回押すだけで 20 万 G 以上を確認なしで使ってしまう |
| B7 | 矢印キーしか使えない(hjkl が使えない) |

## 2. 方針

1. **「次にどこへ行くか」の判断に必要な情報を、1 画面で見せる**: 持っている積荷の売り先を、地図(色)・通常画面(売り先の一覧)・出航先の詳細(売却額の目安と損益)の 3 か所でつなげる(A1, A3)
2. **漂流を目で見せる**: 出航先を選ぶと、地図に「航路」と「合流点」を描く(A2)
3. **確定前に結果を見せる**: 売買では、確定した後の所持金・積荷・価格と損益を先に見せる(A4)。拡張は確認してから実行する(B6)
4. **キーを押す回数を減らす**: 数字キーで個数を直接入力する、カーソルの初期位置を賢く選ぶ、アニメーションを飛ばせるようにする(B1, B4, B5)
5. **ゲームルールは変えない**: 現在価格は今いる島のものだけ見える、という前提は守る。目安は公開されている属性と商品の基準価格だけから計算する

## 3. 検討したこと

- **「属性から計算した目安を見せると、価格を隠すルールが崩れないか」** → 崩れない。属性と商品の基準価格はもともと公開されていて、プレイヤーが暗算できる値を代わりに計算するだけ。揺らぎ(±30%)と自分の売買による価格の変動は反映しないので「目安」と明記する
- **「仕入れ値の記録はゲームの状態を増やす」** → 増えるのは表示用の値だけで、ルールには影響しない。部分的に売ったときは平均原価法で按分する。整数の切り捨てがあっても、全部売れば必ず 0 に戻る(`Cost × n / n = Cost`)
- **「モードを増やすと複雑にならないか」** → 増やすのは拡張の確認だけにする。売買の切り替えはモード内のフラグを反転するだけで済む
- **却下した案**
  - 画面幅に合わせてパネルを広げる: 100 桁で収まるレイアウトが前提なので、広げても新しく見せる情報がない。中央寄せだけにする
  - 出航先を移動日数順に並べ替える: 島の漂流で毎ターン順番が変わり、かえってわかりにくい。ID 順のままにする
  - マウス操作: キーボードで完結するゲームで、端末によって挙動が違う。効果に見合わない
  - 「利益が最大になる個数」の自動提案: 売る島の価格が見えないので正しく計算できない。見せるのは目安までにする
- パネルの seed 表示は外す(遊んでいる間は不要で、1 行分の場所をとる)。終了の確認と終了画面には出す

## 4. 何を変えたか

| 課題 | 変更 |

| A1 | 地図で売り先の島を橙にし、通常画面に「積荷の売り先」(需要がある島と移動日数)を出す |
| A2 | 出航先選択と航行中に、航路 `·` と合流点 `◇` を地図に描く |
| A3 | `game` に仕入れ額(`Cost` / `CostOf`)を足し、売るときの損益を見せる |
| A4 | 売買の確定前に、平均単価・取引後の相場・所持金・積荷を見せる(`Quote` が取引後の価格も返す) |
| A5 | 待機・到着・売買のたびに結果を 1 行で出す。到着時は需要のある積荷を教える |
| A6 | ヘッダに残り日数とスコアを出し、終盤は色で知らせる |
| A7 | キーの説明は、キーを明るく、説明をグレーで描く |
| A8 | 全体を中央に置く。狭い端末では必要なサイズと今のサイズを出す |
| B1 | 数字キーと Backspace で個数を直接入力する |
| B2 | 売買モードのまま Tab / b / s で買う・売るを切り替える |
| B3 | カーソルが取扱なしの品目を飛ばす |
| B4 | 出航先のカーソルを、1 日あたりの目安の損益が最大の島に置く(`Estimate`) |
| B5 | 航行中に何かキーを押すと到着まで飛ばす |
| B6 | 拡張は確認してから実行する |
| B7 | hjkl でも動かせる |

## 5. 設計と実装で決めたこと

- **API を増やしすぎない**: 「取引後の価格」を返す見積もりを別に作ると、見積もりが 2 つになる。内部の `plan` を `Quote` として公開し、戻り値を `(total, price int, err error)` に広げた
- **UI で式を真似しない**: 損益の按分(`CostOf`)、売却目安(`Estimate`)、合流点(`Route`)はすべて `game` に置き、`Sell` と UI が同じ式を使う
- **古いティックを捨てる**: アニメーションを飛ばせるようにしたので、ティックに航行の通し番号をつけた
- **確認のモードは 1 つ**: 終了と拡張の確認を `modeConfirm` にまとめ、`confirmUpgrade` で区別する
- 行数は、売買モードでエラーが出るときがいちばん多く、22 行ちょうどになる

## 6. 実装後の確認で直したこと

- ヘッダの「損益」は `Score()`(積荷を含まない)なので、買った直後に大きなマイナスに見えた → 終了の確認・終了画面と同じ「スコア」に呼び方をそろえた
- 終了画面が行ごとに中央寄せされ、ラベルの位置がそろわなかった → 左揃えのブロックにしてから中央に置いた
- 出航先の詳細に置く予定だった「名産 … / 需要 …」の行は、一覧の属性の列と同じ情報なので外した
- 拡張の確認で増分が要るので、`game` の定数 `upgradeStep` を `UpgradeStep` として公開した
